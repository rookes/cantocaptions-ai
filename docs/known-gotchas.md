# Known gotchas (full rationale)

The long form of the gotchas summarised in CLAUDE.md. Each links to the page with the measurements behind it.


- **VAD import**: Do NOT import via `pyannote.audio.pipelines` — it triggers a NeMo/speechbrain probe. Use `pyannote.audio.core.inference.Inference` directly. See `vads/pyannote.py`.
- **VAD smoothing order**: In `Binarize`, the `max_duration` min-cut must stay the *last* stage. When it ran inside the hysteresis loop it was mutually exclusive with padding/`min_duration_off` (setting either raised `NotImplementedError` whenever `max_duration` was finite — and it always is, since it's the ASR chunk budget), so every region was clipped to its exact threshold-crossing frame, cutting word onsets and tails. Capping the *final* regions also guarantees padding can't push a chunk past `chunk_size`.
- **Alignment emission frame rate**: the align model (`alvanlii/wav2vec2-BERT-cantonese`) has `add_adapter=True, adapter_stride=2`, so its CTC emission runs at ~25 fps while `attention_mask` counts ~50 fps input feature frames. Always convert with `model._get_feat_extract_output_lengths()` before using a mask length to index or trim an emission. Using the mask length directly makes the trim a silent no-op, leaving batch padding on every non-longest row; `_align_segment`'s `ratio = duration / (trellis.size(0) - 1)` then compresses that segment's timestamps toward its start (seconds of drift). `_compute_vad_emissions_batched` logs a warning if the per-segment frame rate varies by >2%.
- **Align model pins the first character to frame 0**: `alvanlii/wav2vec2-BERT-cantonese` emits the utterance's first character at emission frame 0 whenever the audio does not start with speech — and nowhere else, so there is no evidence at the real onset to recover. Suppressing frame 0 just moves it to frame 1, and a dummy leading token (blank, `！`, or a real character) only changes *which* token consumes frame 0. The fix is `align_profiles.TailPrimer`, which removes the trigger; see [alignment.md](alignment.md). Do not try to patch this in the trellis or by editing the emission — masking silent frames reaches barely half the cases and can erase legitimate emissions.
- **tqdm bars**: Use `leave=False` for silent bars, NOT `disable=True`. With `disable=True`, `close()` skips `_decr_instances()`, leaking entries in `tqdm._instances` and causing bar positioning bugs.
- **torchcodec**: Has no wheels on Windows, macOS, or Linux aarch64. Overridden in `pyproject.toml` `[tool.uv]` — do not add it as a direct dependency.
- **Qwen3-ASR context prompt**: `Qwen3ASRProcessor.apply_transcription_request` puts the
  *language name* in the system slot, and the chat template concatenates every system text
  item with **no separator** — so appending context to it emits `"<context>Cantonese"` as
  one run-on string. The official SDK and vLLM do the opposite: system carries the context
  **alone**, and the language is forced by prefilling the assistant turn with
  `language {Lang}<asr_text>`. `_asr_native._build_context_prompts` reproduces the SDK
  shape; `_infer_batch` keeps the plain `apply_transcription_request` path whenever no
  segment carries context, so ordinary runs are unchanged. Batched generation on the
  context path relies on the processor's own `padding_side="left"` default.
- **`get_trellis`/`backtrack` `free_end` must agree**: the forced trellis seeds `trellis[-num_tokens:, 0] = +inf` to terminate its backward walk, and the recurrence carries that `+inf` diagonally until, by the final row, every token column but the last is infinite. A free-end search over such a row has exactly one column to "choose" and silently becomes a forced alignment again. `backtrack(free_end=True)` raises on a forced-built trellis rather than answering wrongly — keep that check.
- **A character's own span can swallow a pause, and no gap test can see it**: CTC fires a character on a frame or two and then sits on it emitting blank until the next thing arrives, and `merge_repeats` reports that whole wait as the character's span. On Police Story 2 that gave `我@330.26-344.19` followed by `覺@344.19-344.35` — fourteen seconds on the first character, a tenth of a second on each one after it — so the subtitle was on screen from 05:30 for a line spoken at 05:44; the same shape at the far edge gave 「唔該警察叔叔」 an 11.8 s cue whose last nine seconds are a pause. Every other guard here compares *consecutive* characters, and there is no gap between characters anywhere in those cues. `alignment._reseat_dwelling_chars` moves any character holding the path for more than `MAX_CHAR_DWELL_SECONDS` onto the frame its own token peaks at, which is where it actually fired. It took the film's longest cue from 17.4 s to 5.4 s and cues over 8 s from 6 to 0.
- **Trimming those cues by loudness instead does not work, and was measured**: the pause inside them is continuous room tone about 12 dB under the dialogue, not silence, and the first frame above any sane threshold is the cue's own first frame. `find_silent_starts`' 30 dB separation guard refuses the region outright, and loosening it does not help because there is no quiet part to find. What reads perceptually as silence is not silence to an energy envelope; the emission says it plainly instead. `align_checks.region_levels` exists for callers that want the levels, with this written on it.
- **A cue's start can come from a blank token's dwell**: `_align_segment` takes a subsegment's start as the min over *all* its characters, and a character out of the align vocabulary has no timing while the punctuation beside it (mapped to blank) can dwell across seconds of silence. Under `--realign`, where a cue spans a whole transcript line, that put one bluey subtitle on screen 8.8 s early. `realign.tighten_cue_spans` anchors cue edges on the first/last *timed, non-blank* character. Note the confidence score is no help here — those cues scored 0.96–0.99. It drops only runs of at most `MAX_DETACHED_RUN` (2) characters and only at the ends: "whichever run is longest" also throws away a correctly-aligned clause whenever a line has a real pause in the middle of it.
- **A cue can come out zero-length, and that invalidates the whole SRT file**: `align()`'s release/trim pass sets each cue's end from the *next* cue's start, so two cues beginning within `align_padding` of each other leave the first with `end == start`. `segmentation._apply_duration_floor` then finds no room and correctly declines to overlap the neighbour — that non-overlap guarantee is right for ASR output and is tested, so do not weaken it. A zero-length cue never displays, and `suber` (hence `utils/suber.py` and the eval harness) trims an epsilon off the end and asserts the duration is non-negative, so it rejects the entire file. `--realign` is what produces coincident cue starts, so `realign.ensure_visible_cues` repairs them there, borrowing from the silence *before* the cue where there is any.
- **Nothing under `--realign` may reorder the transcript**: the line order is the one piece of structure the input actually carries, and two places used to lose it. `_sanitize` sorted placements by `(start, end)`, so a run of lines handed the same instant -- which is what the ASR text match produces when it cannot place a stretch of near-identical short lines -- was permuted by their *ends*; on Police Story 2 four consecutive 唔該 lines came out reversed. It now sorts by line index and clamps a backwards placement with its cursor. Separately, `_interpolate_unplaced` gave every unmatched line the same start (the last matched line's end), which is what stacked them in the first place; it now lays a whole run across the gap with the leftover silence shared equally. Finally `enforce_cue_order` runs immediately before the writer, because the alignment stage's own output is in order and the one inverted pair on Doraemon appears somewhere after it — an out-of-order SRT is rejected outright by `suber`, so that guard is a validity guarantee and belongs last.
- **An alignment chunk can come out with no audio in it**: `build_align_input` derives chunk bounds from the placements, and when the search runs out of audio and strands the rest of the transcript on the final frame those bounds collapse onto `file_end`. The feature extractor needs one whole analysis window and reports a shortfall as `ValueError: negative dimensions are not allowed` from inside numpy, which aborts the run in the alignment stage — on the Doraemon fixture, where the acoustic anchor genuinely does run out of film. `MIN_CHUNK_DURATION` makes such a chunk reach *backwards* for its samples; there is nothing ahead to reach for.
- **A chunk boundary is not an alignment boundary**: chunks exist because the encoder cannot take a whole film at once, and nothing changes in the audio at the tear. `EmissionTimeline` slices across them; do not reintroduce a rule that a transcript segment must live inside one chunk, and do not add a global frame rate to make the arithmetic easier (chunks differ by up to 2%, which smears every timestamp after a join).
- **Neither the emission nor the VAD can tell skipped speech from silence**: both were measured as ways to catch an anchor that jumped over dialogue, and both fail. CTC is peaky, so the align model emits blank for everything it cannot spell — a whole 360 s clip shows 24 s of non-blank frames, and 15 s the search wrongly skipped measured 0.00 s, identical to a real wordless stretch. The VAD speech spans give 1.41 s against 1.52 s for the same pair. The working test is `verify_anchors`, which asks the neighbours.
- **The CTC score is not a per-cue trust signal**: on Police Story 2 it flagged 187 of 2172 lines, nearly all correctly placed, and missed the one that was 48 s out (score 0.733, above the median). `--realign_min_score` is a document-level mismatch detector and is logged only; the per-cue signal is `flag_unconstrained`'s geometry. Do not wire the score back onto cues.
- **A cue with no text corrupts its neighbours, it does not merely waste a line**: ASR returns nothing for some VAD segments (a music-only stretch), and alignment turned each into an empty cue covering that whole segment — 20.2 s of the Bluey fixture, the longest cue in the file. Cue assembly then treats it as an ordinary neighbour: blank text has no punctuation, so pass A reads the join as clean and glues the cues on either side into **one cue spanning the silence between them**. Text cleaning drops the empty cue at the very end, which is why this was invisible in the output and why it survived `--no_clean_text`. `align()` now emits no cue for a segment with no text, and `assemble_cues` refuses one whatever produced it. The test is the *text*, not whether anything aligned: a cue whose characters are all out of the align vocabulary keeps its text and its cue, it just has no word timings. Note pass B is the wrong place for this — it only drops a cue *shorter* than `min_cue_duration`, deliberately, since a long cue with noisy text may still be speech, while an empty one is commonly the longest cue in the file.
- **Most of the `--realign` guards do not transfer to the ASR path, and this was measured**: over two aligned ASR runs (bluey 134 cues, Doraemon 482) the zero-length/inverted count is **0**, out-of-order cues **0**, cue edges sitting on non-speech for over a second **0**, and characters holding the path over a second **1 per file** — the last because `_reseat_dwelling_chars` is already inside `align()` and doing its job. `tighten_cue_spans`' detached-edge trim moves 2 cues on bluey and 12 on Doraemon and changes the aggregate error not at all (median 0.055 → 0.054, p90 1.440 → 1.418, max identical). `find_implausible_cues`' rate test fares worse still: 40 % precision at 5 % recall. Those guards are `--realign`-only because the failures they catch are `--realign`-only — coincident cue starts, a cue spanning a whole transcript line, a placement search that lost its place. What *does* transfer is `find_gapped_cues`, which is why it is not in that list.
- **A backwards jump at a transform breakpoint is a cut, not a bug**: `phi` running *backwards* between two pieces looks like a monotonicity violation and is not one — it is what a cut *interval* looks like collapsed to a point. Widen it back out and monotonicity is exact: for slope `a` and `delta = b_next - b_prev < 0`, solving `phi_prev(c0) == phi_next(c1)` gives `c1 - c0 = abs(delta) / a`, so `phi` is continuous and non-decreasing with the open interval `(c0, c1)` excised from its domain — that interval being source time this recording has no counterpart for. `Break` therefore stores an interval, not a signed jump. Do not "fix" this by forcing breakpoints to be non-decreasing: that deletes cuts from the model entirely and leaves nothing able to express the case `--realign_mode sync` exists for. Inside a cut `Transform.__call__` returns the cut's own image, which is the continuous extension from both sides and is what `--realign_cut_policy keep` stacks its orphaned cues on.
- **Mode `sync` must not be handed to cue assembly's duration floor**: its whole contract is that the subtitle's proportions survive the round trip, and pass D would quietly stretch any cue the transform made shorter than `min_cue_duration`. `transcribe.py` passes `min_cue_duration=0` for that mode (which turns passes B–D off) and skips stage 4 alignment entirely for its items, rather than aligning and then overriding — that is also why it needs no `tighten_cue_spans` or `strip_sentinels`, having neither words nor sentinels. `ensure_visible_cues` and `enforce_cue_order` still run, because SRT validity is not negotiable. This is the one place the guarantee can leak silently, so it is pinned by test.
- **A cut is not evidence of a speed change, and fitting slope independently per piece throws away most of the evidence for it**: an edit removes or adds content, it does not change how fast the surviving footage plays, so the file's speed is one property of the whole timeline. Letting the segmentation DP's per-piece model estimate slope independently in each piece splits the anchor budget three ways and multiplies each piece's own slope variance — which surfaces as *drift that grows within a piece and resets at the next cut*, not as random scatter. Measured on the ReZero Blu-ray: three independently-fit slopes disagreed by up to 7e-4 (several tenths of a second of within-piece drift), and correcting each for its own reported drift converged them to four decimal places — the signature of one true shared speed, not three different ones. `_shared_slope_refit` (`timefit.py`) fixes it with a pooled, ANCOVA-style common-slope regression over every piece's anchors, run once the DP has already settled on where the breakpoints are; a piece keeps its own slope only when it earns back `SLOPE_PENALTY` over the shared one, so a genuinely mixed-speed splice is not forced together. See [realign.md](realign.md).
- **A piece's shared-slope offset is a weighted median, not a mean, but do not expect that alone to close a real-file gap**: a minority of anchors reading consistently late is invisible to the 4-MAD outlier trim (nothing in it crosses that threshold) but still drags a mean off the typical cue's true position, one piece at a time — a mechanism confirmed with a constructed 12%-skewed-tail synthetic case (median within 0.012 s of true, mean off by 0.03-0.07 s). Measured on the real ReZero Blu-ray, though, switching from mean to median made **no net difference** against hand-checked points (0.202 s vs 0.207 s mean |error|, mixed sign) — that file's anchors evidently are not skewed enough for it to matter, and the synthetic case proves the mechanism, not the diagnosis. Kept as a defensive measure since it costs nothing when the data is symmetric; do not read its presence as proof the piece-level bias problem is solved, and do not re-derive "the anchors must be skewed" as an explanation without measuring it again first. `_weighted_median` costs nothing extra to compute and does not touch the DP's own O(1) prefix-sum cost function, which has no equivalent incremental formula for a median and needs none — it only finds breakpoints, and was already correct.
- **Anchor-and-fill has no ASR-path analogue, and looking for one is a category error**: the search exists because a bare transcript does not say *where* each line is. On the ASR path VAD supplies that, and each cue's audio is the segment it was decoded from, so there is nothing to search, no pointer to lose, and no confidence ordering to impose. The one shared prerequisite — `EmissionTimeline` and exact per-frame times — was already made unconditional, so the ASR path no longer approximates character times with `ratio = duration / (trellis.size(0) - 1)`.
- **pyannote diarization import**: load `Pipeline` from `pyannote.audio.core.pipeline`, not
  `pyannote.audio.pipelines` — the latter's `__init__` imports `speaker_verification`, which probes for
  NeMo/speechbrain/onnxruntime. Same reason as the VAD gotcha above.

- **Windows consoles crash on CJK output unless told otherwise**: a cp1252 console, or stdout
  redirected to a file, raises `UnicodeEncodeError` on the first Chinese character printed,
  which used to kill a run *after* its work was done. `log_utils.make_console_safe()` fixes it in
  `setup_logging`; do not print to the console before logging is set up.
